HIGHLIGHTS
  - THE HOME SCENE IS NOW SERVER-RENDERED INTO THE STATIC EXPORT.
    Before v2.7 the entire home scene (h1, capabilities, projects)
    existed only after client JavaScript ran — crawlers received a
    shell with zero semantic content. The SceneRegistry mount gate
    was removed: the default "home" scene renders during prerender
    (dynamic() SSR), hydrates without mismatch (first client
    render matches the server render), and the URL-determined
    scene correction still happens behind the loading screen
    through the normal transition machinery. The exported
    index.html now carries exactly one h1, the capability
    vocabulary, the featured project names, the workflow stages,
    and crawlable links to every repository destination.
  - HOME PAGE RESTRUCTURED AROUND INFORMATION PRIORITY. The first
    viewport now answers WHO I AM and WHAT I DO: the kicker
    carries the identity (PARSA TAK — RESEARCHER · BUILDER ·
    PROGRAMMER · WRITER · ARTIST), the h1 carries the capability
    (AI systems / Reasoning / Software / Art), and the lead
    sentence describes the actual work. Below the hero, in order:
    a WHAT I CAN DO capabilities grid (8 capabilities, each with
    a one-line explanation of what is actually done), WHAT I HAVE
    ACTUALLY BUILT featured projects (SHEYTAN Local Agent, UHIT,
    FreeIran, RED MAGIC, this website — each with repository,
    notes, and live destinations), and HOW I WORK (the nine-stage
    loop: UNDERSTAND → COMPILE → ASSESS → PLAN → ACT → VERIFY →
    SYNTHESIZE → DELIVER → EVALUATE, in human language). The
    conceptual sections (frameworks, direction) follow the proof,
    not precede it. Visual identity, the RED MAGIC organism, and
    the existing atmosphere are unchanged.
  - WORK SCENE REBUILT AS A FULL PORTFOLIO / RESEARCH INDEX.
    Four FEATURED SYSTEMS (SHEYTAN Local Agent, UHIT, FreeIran,
    WEB) render as rich multi-destination cards (REPOSITORY ↗ /
    SPECIFICATIONS ↗ / LIVE ↗ / field-notes links — never nested
    anchors), followed by four grouped sections covering the rest
    of the verified ecosystem: AI + REASONING (AI Instructions,
    REP, USEF), RESEARCH + EXPERIMENTS (AIST-2026.09,
    ASI-100-Elite-2026.09, RED THEORY), SOFTWARE + ENGINEERING
    (the Contents content infrastructure), and CREATIVE
    TECHNOLOGY (the RED MAGIC organism and the RED MAGIC books).
    Thirteen project entries total, every status and destination
    verified against the actual public repositories; nothing
    invented.
  - ARTICLE COVER ALIGNMENT FIXED. The cover's 980px width is
    gone: title, subtitle, metadata, context chips, cover, TOC,
    and body now form one centered 720px editorial column (the
    header joined the column; the cover margin auto-centers to
    exactly the body width). The cover image keeps intrinsic
    1200×630 dimensions in markup, so nothing shifts after load.
  - COVER ENTER/EXIT MOTION (the flow variant). A new
    data-reveal="flow" behaviour in the single MotionReveal
    IntersectionObserver: entering the viewport reveals the
    cover (restrained opacity + rise + scale settle), leaving it
    eases the image back toward its quiet state, returning
    re-reveals it. Transform and opacity only — no layout shift
    in either direction, no scroll loop, no per-frame React
    state; prefers-reduced-motion degrades to a crossfade with no
    travel; print resolves every reveal state to fully visible
    (an unrevealed cover must never print invisible).
  - BLOG INDEX: VISIBLE PROJECT CONNECTIONS. Every project-
    connected article card now carries a clickable PROJECT ·
    <name> chip in its kicker row that rides the existing
    deep-link project filter (one click narrows the index, one
    more restores it, the chip bar shows why). No parallel
    relationship system — the existing frontmatter field, URL
    state, and filter machinery do all the work.
  - The FreeIran article gained its designed cover
    (freeiran-cores.svg + PNG twin, 1200×630, descriptive alt
    text) — the assets existed but were never wired into the
    frontmatter; all nine articles now ship consistent covers.
  - SEO metadata strengthened, honestly: HOME_TITLE gains
    "Software" (Parsa Tak — AI Systems, Reasoning, Software &
    RED MAGIC); the site description names the four flagship
    projects; keywords add only terms the page visibly presents
    (local AI, AI agents, software engineering, UHIT, FreeIran);
    the home WebPage structured data carries a description
    matching the visible lead. No hidden text, no stuffing, no
    invented entities, no ranking claims.
  - verify:seo extended: a HOME CONTENT VERIFICATION pass reads
    the exported index.html exactly as a crawler receives it and
    fails the build unless the single h1, 18 capability/project/
    workflow phrases, and the four repository destinations are
    present in the visible HTML; scene hashes (#work, #magic,
    ...) are codified as interaction states exempt from in-page
    anchor resolution.
  - Accessibility: project link touch targets expanded to ≥24px
    (mono links kept their visual size, gained padding), the
    Work archive link to 44px.

HOW TO APPLY
  1. Replace your repository contents with these files (allow
     overwrites). All files are complete replacements — no
     patches to merge.
  2. Install dependencies: npm ci (dependencies unchanged; no new
     runtime dependencies at all).
  3. Commit: git add -A && git commit -m "v2.7: visible SEO,
     content hierarchy, work portfolio, blog editorial coherence"
  4. Push: git push origin main
  5. Watch the newest GitHub Actions run (must be green — it runs
     the blog pipeline and the extended SEO verification
     including the new home-content checks), then hard-refresh
     the live site.
